# 内容融合规范（内部维护文档，不随站点发布）

本文件规定"把 Obsidian 笔记融合为 Wiki 正文"的做法。适用于所有学科批次。

## 0. 三种进度必须分开记录

| 状态 | 含义 | 不算完成的内容 |
| --- | --- | --- |
| 已归类 | 笔记已发布并有主题归属（`build-topic-guides.mjs` 生成的索引） | 只出现在索引/链接清单里 |
| 部分融合 | 主题文章已引入该笔记的核心概念，但缺推导、例题或代码 | 只写一句摘要或一段导入 |
| 正文完成 | 笔记中决定结论的解释、假设、推导、例题、图表、代码已进入目标文章对应章节，重复定义已合并 | 整篇原文嵌入、只加链接 |
| 待处理 | 尚未开始或阻塞 | —— |
| 排除 | 明确不发布/不融合（隐私、版权、重复、无独立价值），需写理由 | —— |

## 1. 写作要求

1. **先读再写**：先读源笔记（`content/vault-notes/<学科>/`）与现有主题文章（`content/signal-processing/` 等），再决定章节顺序。
2. 每篇主题文章是一段可独立阅读的学习路径，建议结构：
   - 为什么需要这个概念（引出问题）
   - 定义与适用条件（符号、假设、适用范围）
   - 关键推导或性质（保留原笔记的推导思路，不必逐字照抄）
   - 例题 / 数值例子 / MATLAB、Python 或 Verilog 代码（保留原语言）
   - 易错点与工程注意
   - 前置阅读 / 下一步 / 相关主题（用全小写双链）
3. **保留条件**：公式的适用条件、符号约定、单位、参数（如 $f_s$、$N$、$Omega_c$）必须保留；不能为了缩短而删掉决定结论的前提。
4. **来源标注**：文末用"## 来源与延伸阅读"列出对应的 `[[vault-notes/...]]` 详细笔记；正文中可在关键推导处注明"课程笔记的完整推导见 …"。
5. **去重**：同一概念在多篇笔记重复时，合并为一次解释；不同笔记的差异或矛盾要指出并说明取舍。
6. **不编造**：没有依据的结论标注"待核验"；不能声称跑过的实验/仿真结果。

## 2. 技术约束（违反会导致构建失败或线上 404）

- 文件与目录名：全小写英文短横线；页面标题用 frontmatter `title`（中文）。
- 块级公式 `$$` **必须独占一行**；行内用 `$...$`。
- 双链必须写全路径且与磁盘文件逐字符一致（小写）：`[[signal-processing/digital-filter-structures|数字滤波器结构]]`。
- 引用已发布笔记：`[[vault-notes/dsp/05-filter-structures|数字滤波器结构（详细笔记）]]`。
- 图片只能引用已同步的附件：`![说明](vault-notes/assets/<笔记slug>/fig-01.svg)`（这些路径已存在，不要再新增图片文件）。
- 代码围栏标注语言；不要在代码块里放双链或公式。
- 由 `build-topic-guides.mjs` 生成的 `<!-- topic-index:start -->…<!-- topic-index:end -->` 区块**只能由脚本更新**，手工编辑会被覆盖；人工正文写在标记之外。
- 不要修改 `content/vault-notes/`（同步生成目录），不要修改其他学科目录，不要执行 `git` 或构建命令（由 Lead 统一验证与提交）。

## 3. 交付

- 主题文章（`content/<主题>/`）+ 主题索引页人工部分的更新（保持 marker 区块不动）。
- 学科台账：`notes/fusion/<学科>.md`，表格列：源笔记 | 核心概念 | 目标文章 | 目标章节 | 动作 | 状态。
- 在最终消息中给出：写/改了哪些文件（含字节数）、每篇覆盖的源笔记、未融合清单与原因、以及你对渲染风险的说明。

## 4. 质量示例

DFT/FFT 专题应当讲清：DTFT 频率采样为何得到 DFT、圆周卷积与线性卷积的补零条件、频率分辨率与补零的关系、频谱泄漏与窗函数、FFT 的 DIT 分解与运算量、最后给出可运行的 MATLAB/Python 代码，并链接到详细笔记——而不是只在末尾放两条源文件链接。
